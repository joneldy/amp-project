## Project Overview

This is a React social media application called **Elastik** built with Create React App, AWS Amplify, and GraphQL. It's a full-stack application with a React frontend and an AWS AppSync GraphQL backend.

### Technology Stack
- **Frontend**: React 19.2.0, TypeScript support via Create React App
- **Backend**: AWS Amplify (AppSync GraphQL API, Cognito Authentication, DynamoDB)
- **Testing**: Jest, React Testing Library
- **Linting**: ESLint with react-app configuration

## Amplify Version & GraphQL Syntax

**Important**: This project uses **AWS Amplify Gen 1** with **GraphQL 1 directives**. The schema uses older Amplify-specific GraphQL directives like `@model`, `@auth`, `@key`, and `@connection`. These directives are specific to Amplify Gen 1 and should not be confused with Amplify Gen 2 syntax.

Key Gen 1 directives used:
- `@model` - Transforms a type into a DynamoDB table with CRUD operations
- `@auth` - Defines authorization rules (allow public/owner/private access)
- `@key` - Creates secondary indexes for efficient querying
- `@connection` - Establishes relationships between models

## Architecture

### Data Model
The application has three main entities defined in GraphQL schema (`amplify/#current-cloud-backend/api/myelastikapp/schema.graphql`):

1. **User** - User profiles with authentication via Cognito
   - `id`, `owner` (Cognito identity), `username`, `email`, `bio`, `profilePicture`
   - Relationships: owns Posts and Comments
   - Auth rules: owner can write/update, public can read

2. **Post** - User-generated content with likes
   - `id`, `owner`, `title`, `content`, `imageUrl`, `userID`, `likes`
   - Relationships: belongs to User, has many Comments
   - Indexed by user and creation time (`postsByUser` query)

3. **Comment** - Comments on posts
   - `id`, `postID`, `commenterID`, `owner`, `content`
   - Relationships: belongs to Post and User (commenter)
   - Indexed by post and commenter

### Frontend Structure
- `src/App.js` - Main component (currently a default Create React App template)
- `src/index.js` - React entry point with React 19 StrictMode
- `src/graphql/` - Auto-generated GraphQL operations
  - `queries.js` - Read operations (getUser, listUsers, getPost, listPosts, postsByUser, getComment, listComments, commentsByPost, commentsByCommenter)
  - `mutations.js` - Write operations (auto-generated for create/update/delete)
  - `subscriptions.js` - Real-time subscriptions
  - `schema.json` - GraphQL schema introspection

### AWS Configuration
- **Region**: ap-southeast-1 (Singapore)
- **Authentication**: Cognito User Pools with API_KEY fallback
- **GraphQL Endpoint**: AppSync (configured in `src/aws-exports.js`)
- Amplify config: `src/amplifyconfiguration.json`, `src/aws-exports.js` (auto-generated - do not edit)

## Important Notes

### GraphQL Operations
All GraphQL queries, mutations, and subscriptions are auto-generated by Amplify CLI. They're located in `src/graphql/` and should not be manually edited. Changes must be made in the backend schema and regenerated via Amplify.

### AWS Configuration Files
- `src/aws-exports.js` and `src/amplifyconfiguration.json` are auto-generated by Amplify
- These files contain AWS credentials and API endpoints
- They should NOT be committed if they contain sensitive information (currently protected by `.gitignore`)
- The AWS AppSync API Key in these files has limited scope (read-only for public data)

### Authentication
The app uses AWS Cognito for authentication with:
- Email-based sign-up and login
- MFA disabled (can be enabled in Cognito settings)
- Password policy: minimum 8 characters

### Authorization
Authorization is defined at the GraphQL schema level using `@auth` directives:
- **User**: Owner can manage, public can read
- **Post**: Owner can manage, authenticated users can read, public can read
- **Comment**: Owner can manage, authenticated users can read, public can read

## Common Development Tasks

### Adding a New Feature
1. Update the GraphQL schema in `amplify/backend/api/myelastikapp/schema.graphql`
2. Run `amplify codegen` to regenerate GraphQL operations
3. Build React components in `src/` to consume the new queries/mutations
4. Implement UI and handle loading/error states

### Running Amplify Commands
Amplify CLI commands can be used to manage the backend:
```bash
amplify status          # Check backend status
amplify push            # Deploy changes to AWS
amplify pull            # Sync with cloud backend
amplify codegen         # Regenerate GraphQL operations
```

### Debugging
- React DevTools browser extension recommended for component inspection
- AWS AppSync console provides GraphQL IDE and query testing
- Check CloudWatch logs in AWS Console for backend errors
